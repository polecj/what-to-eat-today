# what-to-eat-today

ai搓的无意义小玩具，旨在解决（存疑）大学生不知道吃什么的难题。纯静态网页，无需安装、构建或后端。

## 三个部分

打开网站直接进入中间的 **是啊吃什么**，没有欢迎页。顶部保留滑动切换动画：

- **之后想吃**：记下平时看到、以后想去的店。
- **是啊吃什么**：按类别管理待抽列表，支持加权随机抽取、历史、抽取/就餐统计、JSON 导入导出和分享码。
- **饭后加餐**：记下路边摊、小吃等加餐选项。

三个清单都采用“类别＋具体名称”的分类记录形式，共用顶部输入区和下方纵向列表布局，电脑和手机使用同一套结构，不再左右分栏。切换分区时输入框及未提交的内容保持不动，仅下方列表左右滑动。

三个清单**分别独立保存**，不会自动合并记录或共用一个文件。统一条目格式是为了后续支持把条目从一个清单移动到另一个清单；**本次尚未添加跨清单移动功能**。

三个清单均可分类、添加、编辑、删除、改名、搜索和排序。可拖动类别或同类条目；手机长按手柄拖动，条目“⋯”菜单也提供上移、下移。“之后想吃”和“饭后加餐”暂不参与随机抽取，抽取、历史、权重和就餐统计仍仅属于“是啊吃什么”。

第一次使用抽取页，可以点击输入区旁的 **教学💡**。教学使用临时列表，不影响真实数据。

抽取窗口常驻展示多行条目的随机滚动带，两侧小三角指向结果中心；日常展示均匀随机挑选当前可抽条目并尽量避免相邻重复，不使用正式抽取权重，也不会增加历史或抽取次数。点击“抽一个”得到结果后，原位置分成“再来一次 / 确定”两个按钮；再次抽取会记录新结果，确认则重新合并为“抽一个”，从刚抽中的条目位于中心的位置继续向上滚动。抽取历史的位置保持不变。

搜索时会临时展开匹配项目所在的大类；清空关键词后恢复搜索前的展开状态。搜索期间手动展开、收起不会改写原有折叠记录。日常展示、抽取过程和最终结果使用同一尺寸、同一字号的多行滚动带；抽取时由快到慢向上滚动，最终选中项停在中间，上下相邻条目仍保留。不使用整块模糊或结果前缀 emoji，启用系统“减少动态效果”时静态展示多行。

## 输入规则

- **类别**：可留空；填写时为 1–20 个汉字、英文字母或数字，不允许空格或标点。不再限制为两个汉字。
- **名称**：1–80 个字符，允许汉字、英文字母、数字、半角空格，以及以下完整符号列表：

```text
( ) （ ） [ ] 【 】 · • & ＆ + ＋ - — _ . , ， 。 ! ！ ? ？ : ： 、 ' ’ ‘ “ ” " / ／ % ％
```

- 除上述字符外全部禁用，包括 emoji、换行、制表符、零宽字符及其他控制字符；类别不允许任何符号或空格。
- 输入或粘贴时自动拦截禁用字符，并使用页面底部不抢焦点的提示；中文输入法选词期间不干预，在完成选词后检查。主列表添加、编辑、类别改名和两个轻清单共用相同规则。
- 保存时去掉首尾空白、合并连续半角空格；导入仍按格式版本校验，不会静默修改文件内容。
- 旧列表中已有的标点、emoji 等内容仍保留；编辑并重新保存时按新规则检查。

## 导入、备份与兼容

所有记录都保存在当前浏览器的 `localStorage` 中，不上传服务器。清理浏览器数据、换浏览器或换站点地址不会自动同步。

每个清单的菜单均可单独导出 JSON、生成 `WTE:` 分享码，以及合并/覆盖导入。操作仅影响当前清单，不是三份清单合并导出。导出继续使用 `version: 2`：

```json
{
  "version": 2,
  "items": [
    "第一食堂 兰州拉面（小碗）",
    "外卖 Burger King",
    "未分类 Burger King",
    "牛肉面"
  ],
  "categoryOrder": ["第一食堂", "外卖", "未分类"]
}
```

新格式按**第一个半角空格**区分类别与名称。未分类且名称含空格时使用显式 `未分类 ` 前缀，页面不会展示这个前缀。没有空格的未分类名称仍直接保存。

旧 JSON（版本 1 或无版本）、数组格式和旧行式分享码按原来的“两字符后接空白”规则解析，避免把旧的未分类 `Burger King` 误拆成类别。浏览器中的旧数据首次使用会迁移，并在本地 `picker_before_v2_backup` 保留迁移前备份；抽取次数、就餐次数、权重及历史同步迁移。迁移保留的旧特殊内容通过 `legacyItems` 兼容标记随新格式往返保存。

“之后想吃”和“饭后加餐”的旧纯名称清单会分别迁移为分类格式，旧条目全部保留为未分类，名称中的空格不会被误识别为类别。迁移前在各自的 `*_before_categories_backup` 键备份原数据，重复打开不会再次转换。

**备份时请分别导出三个清单。导出当前清单不会包含另外两份记录。**

## 文件结构与本地使用

- `index.html`：静态页面入口。
- `assets/app/data.js`：字符校验、存储格式和旧版兼容。
- `assets/app/input-guard.js`：输入、粘贴与中文输入法的实时字符拦截。
- `assets/app/app.js`：抽取、分类管理、统计、导入导出和教学。
- `assets/app/list-store.js`：两个辅助清单的独立存储与旧名称列表迁移。
- `assets/app/sections.js`：三份清单状态切换、共享输入与列表滑动。
- `assets/app/style.css`：桌面/移动端样式及动画。
- `assets/app/example-list.json`：新版示例列表。

可直接打开页面，也可使用任意静态 HTTP 服务器。建议通过固定的 HTTP(S) 地址使用，避免浏览器对本地文件存储和剪贴板能力的限制。

数据格式测试（需要 Node.js，无第三方依赖）：

```sh
node --test tests/*.test.cjs
```
